    0 · Start here: a story in one junction

    Picture a busy crossroads at 8 a.m. The signal is broken, so a traffic officer steps into the middle. She looks down each road, thinks about which queue is longest and who has waited too long, waves one direction through, remembers that the bus lane always fills at 8:15, and radios her colleague at the next junction: "a big group is coming your way". She also follows rules she will never break: she never sends two crossing streams at once.

    That officer is a perfect picture of an agent. This course asks: can software do her job, at every junction, all day, and do it safely? Go 1 answers three questions in plain language:

    1. What is an AI agent, and what changes when its "brain" is a large language model (LLM) like the ones behind chat assistants?
    2. How does an adaptive traffic signal work, and why is it a natural home for an agent?
    3. How do the two link to the big goals of traffic engineering: efficiency, coordination, eco-driving, intelligent transport systems (ITS) and connected and automated vehicles (CAVs)?

    1 · What "agentic AI" means

    An agent is a program that keeps doing four things in a loop, on its own, to reach a goal:

    PerceiveRead the world through tools: detectors, cameras, messages, data from connected cars.
    ReasonCompare options against its goals (less delay, fairness, safety) using rules, a learned policy or a language model.
    ActChange something in the world: keep the green, or switch to the other stage.
    Remember & talkKeep a memory of what happened and send messages to other agents.

    What makes it agentic rather than just "an algorithm" is the combination: it chooses which tools to use, keeps a goal over time, explains itself, works with other agents, and runs with a degree of autonomy. Because it acts in the real world, it always sits behind a safety shield: hard rules it cannot break.

    Environment
    Everything the agent can sense and affect: here, one junction and the traffic on it.
    Tool
    A function the agent can call, such as queue("NS") or priority_requests().
    Goal
    What "good" means, written as weights: e.g. 1 point per queued car, 0.15 points per second of the longest wait.
    Policy
    The rule that turns what it sees into an action. It can be hand-written, learned (reinforcement learning) or produced by a language model.
    Shield
    Hard safety rules checked after the agent decides and before the signal changes: minimum green, maximum green, intergreen, a fairness cap.

    Four properties of an agent

    Computer scientists Michael Wooldridge and Nicholas Jennings (1995) gave a definition that still works well. Software is an agent when it has these four properties:

    PropertyPlain meaningAt a junction
    AutonomyActs without a person approving every stepDecides keep or switch every 2 s on its own
    ReactivityNotices changes and responds in timeA queue builds on the side road, so it shortens the main green
    ProactivenessPursues goals, not only reactingStarts the green early because a platoon is forecast to arrive
    Social abilityCommunicates and cooperates with othersTells the next junction "8 cars in 15 s"; reads bus priority requests

    Agentic AI is the newer word for systems that have a lot of all four: they take multi-step actions, use tools, keep goals over time and work with other agents and people. It is a spectrum, not a yes/no label.

    2 · LLM-based agents: when the brain is a language model

    Since 2023 the most talked-about agents use a large language model (LLM) as their reasoning core, the same kind of model behind chat assistants. To understand what they can and cannot do at a traffic signal, we build them up in five small steps.

    Step 1 · What an LLM actually does

    An LLM is, at heart, a very well-read autocomplete. It was trained on a huge amount of text to do one thing: given the text so far, predict the next piece of text, called a token (roughly three-quarters of a word). It writes a whole answer by predicting one token, adding it, and predicting again.

    • Everything it can "see" right now (instructions, data, earlier messages) must fit in its context window: its working memory for this conversation.
    • It does not look anything up unless we give it a tool to do so. Its knowledge stops at its training date.
    • It picks among likely tokens with some randomness, set by the temperature. The same question can give different answers.
    • When it does not know, it can still produce a fluent, confident guess. That is a hallucination. At a traffic signal a fluent guess is dangerous, which is why the shield exists.

    Inside the autocomplete

    Illustrative scores for the next word; real models choose from about 100 000 tokens

    "The side road has been red for 95 s and 14 cars are waiting, so the signal should ___"

    Low temperature: nearly always the top word. High temperature: more variety, including silly words. For control we want low temperature and a check on every answer.

    Step 2 · From chatbot to agent

    A chatbot answers once and stops. An LLM agent wraps the model in a loop and gives it ways to act:

    LLM agent = LLM (reasoning) + instructions (role and goals) + tools + memory + a loop + guardrails
    Instructions
    A system prompt that sets the role and goals: "You control one junction. Minimise delay; nobody waits more than 90 s; buses and ambulances first."
    Tools
    Functions described to the model in a fixed format (a JSON schema). The model replies with a request like {"tool": "queue", "args": {"approach": "NS"}}; ordinary code runs it and returns the result. This is called function calling. The Model Context Protocol (MCP, 2024) is one open standard for plugging tools into models.
    Short-term memory
    What is in the context window now: the last few observations and decisions.
    Long-term memory
    A store the agent can search, e.g. past incidents or the signal timing manual. Fetching relevant pages into the prompt is called retrieval-augmented generation (RAG).
    Planning
    Breaking a goal into steps before acting ("first check priority requests, then queues, then decide").
    Guardrails
    Checks outside the model: the reply must be valid JSON, the action must be on an allowed list, and the safety shield must pass it.

    Step 3 · Think, act, observe: the ReAct loop

    The most common way to run an LLM agent is ReAct (Yao et al., 2023): the model alternates a short Thought ("what do I need to know?"), an Action (a tool call) and an Observation (the tool's answer), until it gives a final answer. Then the guardrails check it before anything happens in the street. Step through four situations; the last two show what goes wrong and how the design catches it.

    Step 4 · Common designs (patterns)

    Not every job needs a free-running agent. A useful rule from practice: use the simplest design that works, and add autonomy only when the task truly needs it.

    PatternHow it worksTraffic example
    Single callOne prompt, one answer, no tools"Explain this timing plan to a councillor in plain words"
    Prompt chainFixed steps, each LLM call feeds the nextSummarise yesterday's detector log → list anomalies → draft the morning report
    RouterThe LLM sorts a request and sends it to the right handlerA citizen complaint goes to "signal timing", "faulty lamp" or "not ours"
    ReAct tool loopThink, call a tool, observe, repeatDiagnose why queues grew on Main St using detector and incident tools
    Plan and executeWrite a plan first, then carry out each stepPrepare signal plans for a stadium event: list junctions, simulate, compare
    ReflectionThe agent critiques its own result and tries again (Reflexion, Shinn et al., 2023)After a simulated run shows long side-road waits, it revises its plan
    Orchestrator and workersA lead agent splits the job among specialist agentsOne agent per junction, a corridor agent assigning targets
    Human approvalThe agent proposes; a person approves before it actsNew plan for tomorrow is applied only after the operator clicks "approve"

    Step 5 · Fast and slow: where an LLM belongs

    Signals work on several clocks at once. Hardware conflict monitors react in milliseconds; keep-or-switch choices come every 1–2 seconds; plans change over minutes; strategy over hours. A large LLM call takes from under a second to several seconds, costs money and can fail. So most designs give the LLM the slow, thoughtful jobs and leave the fast loop to rules or a learned policy.     LLM agents in traffic signal research so far

    Research groups have tried LLMs in four roles. Go 3 looks at the gaps; here is the map:

    LLMs are good atLLMs are weak at
    Reading messy, mixed information (incident text, sensor faults, events)Fast, repeated decisions (seconds matter at a signal)
    Common-sense handling of rare cases they were never trained onExact arithmetic and keeping numbers straight
    Explaining a decision in plain words to operators and the publicGiving the same answer twice (non-determinism)
    Using tools: simulators, databases, timing manualsResisting instructions hidden in data (prompt injection)
    The big idea for Go 1: an LLM is a powerful advisor and planner, not a replacement for the safety system. The fast loop stays simple and certified; the LLM works above it, and everything it proposes goes through the shield.

    3 · How an adaptive traffic signal works

    A signal shares one piece of road between conflicting streams by giving each stage a turn. One round of all stages is a cycle; how the cycle is shared is the split; when a junction's cycle starts relative to its neighbour is the offset. Between greens comes the intergreen (yellow + all-red), which is lost time.

    Fixed time
    A stored plan, the same every cycle. Cheap and predictable, but blind to today's traffic.
    Actuated
    Detectors at the stop line extend the green while cars keep arriving and end it after a gap.
    Adaptive
    A system measures demand and re-optimises cycle, split and offset continuously, e.g. SCOOT (model-based, upstream detectors) and SCATS (degree of saturation at the stop line).
    Max-pressure
    A simple decentralised rule: serve the stage whose waiting vehicles minus vehicles on its exit is largest.
    Agentic
    Adaptive control framed as an agent: tools, goals, memory, communication, explanations and a shield. It can use any of the above as tools.

    We judge controllers by delay (extra time compared with free flow), stops, queue length, the longest wait (fairness) and emissions.

    Signal 101: how much traffic can a green carry?

    One lane of queued cars leaves the stop line at about 1800 vehicles per hour of green (one car every 2 s), the saturation flow. If a road gets green for a share g/C of the cycle, its capacity is 1800 × g/C. Dividing demand by capacity gives the degree of saturation x: below about 0.9 traffic clears each cycle; near or above 1 queues grow without limit. An adaptive system, or an agent, is constantly re-sharing the cycle to keep x low on every approach.

    4 · Linkage 1: efficiency

    Efficiency means moving the most people with the least delay. An agent gets there by measuring instead of guessing: queues, arrivals and how full the exits are. One powerful signal is pressure: cars waiting to enter minus cars already on the exit. Serving the highest pressure keeps the network flowing and, importantly, avoids pushing cars into a road that is already full (spill-back).

    5 · Linkage 2: coordination

    Junctions close together should not act alone. If each upstream green is timed so that its platoon reaches the next junction on green, traffic rides a green wave. Classic systems set offsets centrally. Agents can instead talk: the upstream agent tells its neighbour "about 8 cars will reach you in 15 s", and the neighbour holds or starts its green for them.     6 · Linkage 3: eco-driving

    Every stop costs fuel: braking wastes energy and accelerating from rest burns more. If the signal tells approaching cars when it will turn green, a connected car can slow down early and glide through instead of stopping. This is GLOSA, Green Light Optimal Speed Advisory, using SPaT (Signal Phase and Timing) messages. There is a catch for adaptive control: an agent that keeps changing its mind cannot promise a time.     8 · Linkage 5: autonomous and connected vehicles

    A connected vehicle (CV) exchanges data with the infrastructure and other vehicles. An automated vehicle (AV) drives itself to some level (SAE levels 0 to 5). A CAV is both. For signal agents CAVs matter in three ways:

    • New eyes: CAVs report position and speed, so the agent can estimate queues without loops, if enough vehicles are connected.
    • New hands: CAVs can follow speed advice (eco-driving) or even platoon through on green.
    • New responsibility: mixed traffic (humans + CAVs) for decades means the agent must work at every penetration level.

    9 · Guardrails and levels of autonomy

    Traffic signals are safety-critical. A sensible design gives the agent freedom only inside a box the engineer can certify:

    LevelWho decidesExample
    0 · ManualEngineerFixed-time plans designed offline
    1 · AdvisoryAgent suggests, operator approvesAgent proposes new splits for tomorrow
    2 · SupervisedAgent acts within limits, operator watchesAgent chooses keep/switch; shield + centre oversight
    3 · CollaborativeAgents coordinate with each otherCorridor agents share platoon forecasts
    4 · AutonomousAgents set their own sub-goalsNetwork agents re-plan during an incident, logged for audit
    The shield is never optional: minimum green, maximum green, intergreen and pedestrian times are checked outside the agent, whatever kind of AI is inside.

    Extra guardrails when the brain is an LLM

    1. Strict output format: only replies that parse as the expected JSON are used; anything else counts as "no change".
    2. Allowed actions only: the agent can choose from a short list (keep, switch, request plan change), never free-form commands.
    3. Data is not instructions: messages, sensor text and web pages are wrapped and labelled as data, so text like "ignore your rules" inside them is not obeyed.
    4. Check facts against tools: if the reason quotes a queue of 40 but the tool said 4, the answer is rejected.
    5. Safe fallback: if the LLM is slow, offline or keeps failing, the junction runs its normal actuated or fixed plan.
    6. Log everything: every prompt, tool call, answer and shield decision is stored, so engineers can audit and improve the agent.

    10 · Recap and memory route

    1. An agent loops perceive → reason → act, with tools, goals, memory and messages; it shows autonomy, reactivity, proactiveness and social ability, and comes in five kinds from simple reflex to learning.
    2. An LLM predicts the next token; an LLM agent adds instructions, tools, memory, a ReAct loop and guardrails. It is slow and can hallucinate, so it plans and advises above a fast, certified loop.
    3. Adaptive signals change cycle, split and offset; capacity is 1800 × g/C per lane; we score them by delay, stops, longest wait and emissions.
    4. Efficiency: measure queues and pressure; avoid spill-back.
    5. Coordination: neighbours share forecasts to make green waves.
    6. Eco-driving: SPaT + GLOSA turn stops into glides, if the signal is predictable.
    7. ITS: sensing, V2X, edge controller, agent, control centre.
    8. CAVs: new eyes, new hands, mixed traffic for a long time.
    9. Shield: hard rules outside the agent; autonomy is granted in levels; LLMs get extra guardrails.
